# AI Solo Founder Social Series

Create finished, publishable artifacts rather than only copy, prompts, or a storyboard. Preserve the series as an honest build-in-public record, not a success story or AI product advertisement.

## Load the production system

1. Read `D:/SNS/carousels/brand-config.json` when it exists.
2. Read `references/series-contract.md` completely.
3. Read and follow `editorial-webtoon-social-bundle`.
4. Read and follow `script-to-social-bundle`.
5. Read and follow `instagram-carousel`.
6. Read `imagegen` before generating or editing raster illustrations.
7. Use HyperFrames only when the user requests a rendered video file. Animated presentation HTML does not require it.

The square `1080 x 1080` series contract overrides any downstream 4:5 default.

## Establish continuity without repeating templates

1. Inspect the latest relevant projects under `D:/SNS/carousels/YYYY/MM/`.
2. Reuse the approved protagonist identity, editorial illustration finish, palette, and information hierarchy when they still fit.
3. Do not copy the previous cover composition or repeat one layout across the deck.
4. Preserve earlier episode folders. Create a new numbered sibling project.
5. Check the prior episodes' claims and phrasing before writing. Avoid retelling earlier retirement, career, or experiment context unless the new brief explicitly requires it.

## Produce the complete package

Create the following in one project folder:

- editable square carousel HTML;
- one `1080 x 1080` PNG per card;
- carousel contact sheet;
- recomposed animated `presentation-16x9.html`;
- one `1920 x 1080` presentation PNG per card;
- presentation contact sheet;
- at least three representative mid-animation frames;
- publish-ready caption;
- image prompt and asset notes;
- source/editorial note when a public figure, quotation, product, or factual claim appears;
- ZIP containing only the final carousel PNGs.

When the user asks for English, create a separate `-en` sibling project. Reuse the approved scene images, translate the narrative and UI labels naturally, recompose line breaks for English, and export and validate the full package again. Do not merely provide translated copy.

## Build the story visually

Map every card to one clear claim and one visual job before implementing it.

- Use the protagonist for lived action, emotion, conflict, or a decision.
- Use situation-specific scenes, real working UI, objects, diagrams, timelines, comparisons, or process maps for explanatory claims.
- Make the image communicate the claim before the body copy is read.
- When the story says a prompt produced a web page, show the command and a believable rendered web interface in the same causal scene.
- Keep generated illustrations free of embedded copy; render all important text and UI labels in HTML.
- Keep the tone adult, editorial, documentary, approachable, and specific.

## Validate before delivery

1. Export every carousel and presentation image.
2. Rebuild and inspect both contact sheets.
3. Inspect long-copy cards individually at full resolution.
4. Inspect at least three mid-animation frames.
5. Fix clipping, overlaps, weak contrast, mismatched imagery, or generic portrait repetition.
6. Run the editorial bundle validation script with the actual slide count.
7. Confirm the ZIP contains exactly the final carousel PNG count.
8. Search text files for `comindworks`, `CoMindWorks`, `@comindworks`, unintended watermarks, and any wording the user explicitly removed.

## Deliver

Lead with the completed contact sheet. Provide direct links to:

- downloadable PNG ZIP;
- editable carousel HTML;
- animated presentation HTML;
- carousel and presentation contact sheets;
- caption;
- project folder or PNG directories when useful.

Report the verified card count, image dimensions, ZIP entry count, and validation result.
